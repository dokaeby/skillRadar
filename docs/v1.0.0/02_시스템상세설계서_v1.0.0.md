## 3. 데이터 흐름

### 3.1 일일 수집 (스케줄/수동 공용)

1. `collect_all`이 플랫폼 순회 → 플랫폼별 실패는 격리(rollback 후 계속)
2. `collect_platform`:
   - `queries.yaml`의 플랫폼 쿼리 각각 `search_repositories` 호출
   - `archived`/`fork` 제외, `full_name` 기준 병합(최대 star 유지)
   - star 내림차순 Top 10 선정
   - 직전 스냅샷(`collected_date < 오늘` 중 최신)에서 repo→stars 맵 작성 → `stars_today` 계산
   - 같은 (platform, collected_date) 스냅샷이 있으면 삭제 후 재생성(멱등)
   - 각 항목: `fetch_readme` → `content_hash` 계산 → 캐시 조회 → 미스 시 `Summarizer.summarize`
   - README/LLM 실패는 해당 항목만 폴백, 수집 중단 없음
3. `notify_daily_top`: 최신 수집일의 플랫폼별 Top1을 구독자에게 푸시

### 3.2 조회

- `/api/trending`: 요청 날짜 스냅샷 우선, 없으면 해당 플랫폼 최신 스냅샷 폴백
- `lang=ko|en|zh` → `SnapshotItem.summary_for(lang)` → 없으면 description 1줄 폴백

## 4. 외부 연동

| 연동 | 방식 | 장애 처리 |
|---|---|---|
| GitHub Search API | `GET /search/repositories` (인증 시 분당 30회) | 403/429/5xx + 네트워크 오류에 지수 backoff 최대 3회, `Retry-After` 헤더 우선 |
| GitHub README | `GET /repos/{full}/readme?raw=1` (redirect follow), 실패 시 contents API base64 폴백 | 실패 시 빈 문자열 → 요약은 description만으로 진행 |
| LLM | OpenAI-호환 `POST {LLM_BASE_URL}/chat/completions` | 호출 실패·JSON 파싱 실패·형식 오류 시 1회 재시도, 최종 description 폴백 |
| Web Push | `pywebpush.webpush` + VAPID | 404/410 응답 시 구독 자동 삭제, 그 외 예외는 로그 후 계속 |

## 5. 설정·보안

- `Settings`(pydantic-settings, frozen): `GITHUB_TOKEN`, `LLM_API_KEY`, `ADMIN_TOKEN` 등 `SecretStr` 처리
- `DATABASE_URL` 스킴 검증: `sqlite:///`, `postgresql://`, `postgres://`, `postgresql+psycopg://`만 허용
- `LLM_BASE_URL`은 https(또는 localhost http)만 허용
- `/api/admin/refresh`는 `Authorization: Bearer <ADMIN_TOKEN>` 필수, 미설정 시 항상 401
- `app_env=debug`일 때만 Swagger(`/docs`) 노출, 기본값은 release 성격 안전(`debug` 기본이나 운영 시 `APP_ENV=release` 권장)

## 6. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| Rate limit | GitHub 검색 분당 30회(인증) 준수 — 플랫폼당 쿼리 3회 × 3 플랫폼 = 9회/일 |
| 비용 | content_hash 캐시로 동일 repo+README 재요약 방지 |
| 격리 | 플랫폼 수집 실패·항목 요약 실패가 전체 작업을 중단시키지 않음 |
| 영속성 | Render 무료 플랜 ephemeral 디스크 대응 — `DATABASE_URL`을 Postgres로 바꾸면 코드 변경 없이 전환 |
| 시간대 | 수집일·"오늘" 판정은 Asia/Seoul (`today_kst`) |
