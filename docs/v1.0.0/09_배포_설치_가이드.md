## 1. 로컬 설치

### 1.1 요구사항

- Python 3.12 이상 (개발 검증: 3.15)
- Git

### 1.2 설치·실행

```bash
git clone <repo-url> skillRadar
cd skillRadar
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env               # 값 채우기 (아래 1.3)
uvicorn app.main:create_app --factory --host 0.0.0.0 --port 8000
```

브라우저: http://localhost:8000

개발 모드(기본 `APP_ENV=debug`)에서는 `/docs` Swagger 사용 가능.
운영 배포 시 `APP_ENV=release`로 두면 문서 경로가 비활성화된다.

### 1.3 환경변수

`.env.example` 참조. 필수/권장 구분:

| 변수 | 필수 | 설명 |
|---|---|---|
| `GITHUB_TOKEN` | 권장 | GitHub PAT. 검색 rate limit 10→30 req/min |
| `LLM_API_KEY` | 권장 | OpenAI-호환 API 키. 없으면 description 폴백 요약 |
| `LLM_BASE_URL` | - | 기본 `https://api.openai.com/v1` |
| `LLM_MODEL` | - | 기본 `gpt-4o-mini` |
| `ADMIN_TOKEN` | 권장 | `/api/admin/refresh` 인증. 미설정 시 refresh 항상 401 |
| `DATABASE_URL` | - | 기본 `sqlite:///./skillradar.db`. Postgres: `postgresql://user:pass@host/db` |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | - | Web Push. 미설정 시 푸시 비활성 |
| `SCHEDULE_HOUR` / `SCHEDULE_TIMEZONE` | - | 기본 6 / Asia/Seoul |

VAPID 키 생성 예시:

```bash
pip install py-vapid
python - <<'EOF'
from py_vapid import Vapid
v = Vapid(); v.generate_keys()
print("VAPID_PUBLIC_KEY=" + v.public_key_urlsafe())
print("VAPID_PRIVATE_KEY=" + v.private_key_urlsafe())
EOF
```

`VAPID_SUBJECT`는 `mailto:` 주소.

## 2. Render 배포

### 2.1 Web Service 생성

**방법 A — Blueprint (권장)**

1. Render Dashboard → New → Blueprint → 이 repo 연결
2. `render.yaml` 자동 인식 → envVars 중 `sync: false` 항목에 값 입력 후 Apply

**방법 B — 수동**

- Runtime: Python
- Build: `pip install -r requirements.txt`
- Start: `python -m uvicorn app.main:create_app --factory --host 0.0.0.0 --port $PORT`
  - `Procfile`도 동일 명령을 제공 (`web:`)
- Health check: `/` 또는 `/api/trending`

### 2.2 무료 플랜 주의사항

| 이슈 | 내용 | 대응 |
|---|---|---|
| Ephemeral disk | 재시작·재배포 시 SQLite 파일 초기화 → 데이터 유실 | Render Postgres 생성 후 `DATABASE_URL=postgresql://...` 설정. 코드는 `postgresql+psycopg`로 자동 전환 |
| Spin-down | 무료 인스턴스 유휴 시 sleep → APScheduler 미발화 가능 | 정확한 매일 실행 필요 시 Render Cron Job으로 `python -m app.cli_collect` 매일 등록 권장 |
| Cold start | 첫 요청 지연 | 허용 범위 내 |

### 2.3 수동 수집 (운영)

```bash
curl -X POST https://<your-app>.onrender.com/api/admin/refresh \
  -H "Authorization: Bearer $ADMIN_TOKEN"
```

또는 Render Shell에서 `python -m app.cli_collect`.

## 3. 수집 쿼리 커스터마이징

`app/queries.yaml`을 수정해 플랫폼별 검색 쿼리를 변경한다.
각 쿼리는 GitHub 검색 문법을 그대로 사용하며 `archived:false fork:false`를 포함해야 한다.
수정 후 재배포(또는 재시작)하면 다음 수집부터 적용된다.

## 4. 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| `/api/trending` items 빈 배열 | 아직 수집 전 | `/api/admin/refresh` 호출 또는 다음 스케줄 대기 |
| 요약이 description 반복 | `LLM_API_KEY` 미설정 또는 LLM 장애 | 키 확인, 로그에서 `LLM 호출 실패` 확인 |
| 푸시 버튼 무반응 | VAPID 키 미설정 | `vapid-key` API가 `{"key":""}` 반환 |
| 401 on refresh | `ADMIN_TOKEN` 불일치/미설정 | env 확인 |
| DB 오류 on Postgres | `psycopg` 미설치 | `requirements.txt`의 `psycopg[binary]` 확인 |
| 스케줄 미실행 | spin-down 또는 시간대 | `SCHEDULE_TIMEZONE` 확인, Cron Job 대안 검토 |
