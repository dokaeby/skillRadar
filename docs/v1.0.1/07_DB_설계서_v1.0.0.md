# SkillRadar DB 설계서 v1.0.0

| 항목 | 기준 |
|---|---|
| 작성일 | 2026-11-18 (Asia/Seoul) |
| 구현 기준 | `src/backend/models.py` (SQLAlchemy 2.0 선언형) |
| DB | 로컬·기본 SQLite / 운영 PostgreSQL (`DATABASE_URL`로 전환) |
| 스키마 관리 | `Base.metadata.create_all` (앱 시작 시 자동, Alembic 미사용) |
| 테이블 수 | 3개 (`snapshots`, `snapshot_items`, `push_subscriptions`) |

## 1. 설계 원칙

- 스냅샷 패턴: 수집일 단위로 랭킹을 통째로 보존 → 과거 랭킹 조회·증감 계산의 기준
- `UNIQUE(platform, collected_date)`로 일 1회 수집 보장, 재수집은 항목 교체(멱등)
- 요약은 `summary_en/zh/ko` JSON 컬럼에 3줄 배열로 저장 (비정규화 스냅샷 — 요약은 해당 시점 README 기준)
- `content_hash` 인덱스로 요약 캐시 조회 가속
- `stars_today`는 저장 시 계산한 파생값(스냅샷 간 diff)

## 2. 테이블 정의

### 2.1 snapshots — 수집 스냅샷

| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| id | INTEGER PK | N | 자동 증가 |
| platform | VARCHAR(32) | N | `claude`/`chatgpt`/`gemini` |
| collected_date | DATE | N | Asia/Seoul 기준 수집일 |
| created_at | DATETIME | N | 서버 기본값 `func.now()` |

**제약**: `UNIQUE(platform, collected_date)` (`uq_snapshot`)
**관계**: `items` 1:N cascade delete-orphan, `rank` 순 정렬

### 2.2 snapshot_items — 스냅샷 내 저장소

| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| id | INTEGER PK | N | 자동 증가 |
| snapshot_id | INTEGER FK→snapshots.id | N | 소속 스냅샷 |
| rank | INTEGER | N | 1~10 랭킹 |
| repo_full_name | VARCHAR(255) | N | `owner/repo` |
| repo_url | VARCHAR(500) | N | GitHub HTML URL |
| description | TEXT | Y | GitHub description 원문 |
| stars | INTEGER | N | 수집 시점 star 수 (기본 0) |
| stars_today | INTEGER | Y | 직전 스냅샷 대비 증가분 |
| language | VARCHAR(100) | Y | 주 언어 |
| topics | JSON | N | GitHub topics 배열 (기본 `[]`) |
| readme_excerpt | TEXT | Y | README 앞 최대 3000자 |
| summary_en | JSON | Y | 영어 3줄 요약 배열 |
| summary_zh | JSON | Y | 중국어 3줄 요약 배열 |
| summary_ko | JSON | Y | 한국어 3줄 요약 배열 |
| content_hash | VARCHAR(64) | Y | sha256(description+README) — 캐시 키, 인덱스 |
| created_at | DATETIME | N | 서버 기본값 |

**제약**: `UNIQUE(snapshot_id, repo_full_name)` (`uq_snapshot_item`)
**인덱스**: `content_hash`

### 2.3 push_subscriptions — Web Push 구독

| 컬럼 | 타입 | NULL | 설명 |
|---|---|---|---|
| id | INTEGER PK | N | 자동 증가 |
| endpoint | VARCHAR(1000) | N | Push 서비스 endpoint, UNIQUE |
| keys_json | TEXT | N | `{p256dh, auth}` JSON 문자열 |
| created_at | DATETIME | N | 서버 기본값 |

## 4. 쿼리 패턴

| 용도 | 쿼리 |
|---|---|
| 당일 스냅샷 조회 | `Snapshot.platform == p AND collected_date == d` |
| 최신 스냅샷 폴백 | `platform == p ORDER BY collected_date DESC LIMIT 1` |
| 직전 star 맵 | `collected_date < d ORDER BY collected_date DESC LIMIT 1` → items 순회 |
| 수집일 목록 | `platform == p ORDER BY collected_date DESC LIMIT 30` |
| 요약 캐시 | `repo_full_name == x AND content_hash == h AND summary_en IS NOT NULL ORDER BY id DESC LIMIT 1` |
| 멱등 재수집 | 기존 스냅샷 `session.delete` → cascade로 items 삭제 |

## 5. 마이그레이션·운영 정책

- 스키마 변경 없음 상태로 `create_all`만 사용. 컬럼 추가 시 Alembic 도입 검토
- Render 무료 플랜: ephemeral 디스크 → 재시작 시 DB 초기화. Postgres `DATABASE_URL` 전환 시 코드 변경 불필요 (`make_engine`이 `postgresql+psycopg`로 정규화)
- SQLite 동시성: `check_same_thread=False`, 서비스는 요청/작업 단위 짧은 세션 사용
