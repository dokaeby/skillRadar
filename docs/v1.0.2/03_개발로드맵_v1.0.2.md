## 2. 완료된 마일스톤 상세

- **수집 파이프라인 (v1.0.1 개편)**: `graph/pipeline.py`의 LangGraph StateGraph가
  collect → dedupe_filter → sanitize → classify → summarize → verify → rank → related 순으로 실행.
  dedupe_filter에서 star 상위 10개(`_TOP_K`)만 남겨 분류·요약·검증 LLM 비용을 제한한다.
- **"오늘 증가 star"**: 직전 스냅샷 diff 방식으로 구현 (GitHub API에 일별 증가량 미제공)
- **요약 신뢰성**: content_hash 캐시, JSON 재시도(최대 3회), description 폴백 + 한국어 Google/MyMemory 번역, verify 불합격 시 재요약 최대 2회 후 `unverified`
- **분류·랭킹**: taxonomy 8종 라벨+신뢰도(`judge_model`), `rank_score` 저장, topic-repos 정렬에 반영
- **주제 탐색**: `/api/topics`(최근 30일 관심순 상위 50), `/api/topic-repos`, `/api/related-topics` + 사이드바/칩 UI
- **UI**: Jinja2 SSR + TypeScript 바닐라(`src/frontend/app.ts` → `src/backend/static/*.js`), Pretendard Variable, 다크모드 기본, 라이선스 배지, PWA(manifest/sw.js)
- **푸시**: VAPID 기반 Web Push, 구독 만료(404/410) 자동 정리
- **평가·품질**: 골든 데이터셋 10개(`eval/dataset.json`) + `run_eval` CLI, 첫 실행 accuracy 1.0 (`docs/experiments/`), pyright 0 errors
- **배포**: Vercel serverless(`skill-radar-liart.vercel.app`), `vercel.json` Cron이 `/api/admin/refresh`를 매일 호출(UTC 21:00 = KST 06:00), Supabase Postgres pooler

## 4. 리스크 및 대응

| 리스크 | 영향 | 대응 |
|---|---|---|
| GitHub rate limit 초과 | 수집 누락 | 백오프 재시도 + `GITHUB_TOKEN` 권장 |
| LLM 비용/장애 | 요약 품질 저하 | 캐시 + Top10 컷 + 폴백으로 서비스 유지. 분류·검증 실패는 각각 other/fail-open 처리 |
| Vercel serverless 제약 | 장시간 수집 타임아웃 가능 | `vercel.json` Cron + `/api/admin/refresh`. 필요 시 `cli_collect` 대안 |
| 무료 플랜 DB 초기화 | 데이터 유실 | Supabase Postgres 사용 중 — `DATABASE_URL`만 교체하면 전환 가능 |
