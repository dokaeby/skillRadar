## 1. 로컬 설치

### 1.1 요구사항

- Python 3.12 이상 (개발 검증: 3.15)
- Node.js (프론트엔드 TS 빌드용)
- Git

### 1.2 설치·실행

```bash
git clone <repo-url> skillRadar
cd skillRadar
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
npm install && npm run build       # frontend TS → src/backend/static/*.js
cp .env.example .env               # 값 채우기 (아래 1.3)
uvicorn backend.main:create_app --factory --host 0.0.0.0 --port 8000
```

브라우저: http://localhost:8000

개발 모드(기본 `APP_ENV=debug`)에서는 `/docs` Swagger 사용 가능.
운영 배포 시 `APP_ENV=release`로 두면 문서 경로가 비활성화된다.

### 1.3 환경변수

`.env.example` 참조. 필수/권장 구분:

| 변수 | 필수 | 설명 |
|---|---|---|
| `GITHUB_TOKEN` | 권장 | GitHub PAT. 검색 rate limit 10→30 req/min |
| `LLM_API_KEY` | 권장 | OpenAI-호환 API 키. 없으면 description 폴백 요약 + 분류 other 처리 |
| `LLM_BASE_URL` | - | 예: Gemini OpenAI-호환 엔드포인트 |
| `LLM_MODEL` | - | 요약 생성 모델 |
| `LLM_JUDGE_MODEL` | - | 분류/검증/채점 모델. 비우면 `LLM_MODEL` 사용 (`.env.example` 기본 `gemini-3.5-flash-lite`) |
| `ADMIN_TOKEN` | 권장 | `/api/admin/refresh` 인증. 미설정 시 refresh 항상 401 |
| `CRON_SECRET` | 권장 | Vercel Cron 자동 주입 Bearer 토큰. `ADMIN_TOKEN`과 동일 값 권장 |
| `DATABASE_URL` | - | 기본 `sqlite:///./skillradar.db`. 운영: Supabase Postgres pooler `postgresql+psycopg://...pooler.supabase.com:5432/postgres` |
| `VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | - | Web Push. 미설정 시 푸시 비활성 |
| `SCHEDULE_HOUR` / `SCHEDULE_TIMEZONE` | - | 기본 6 / Asia/Seoul (로컬 APScheduler용) |
| `TRANSLATE_FALLBACK` | - | 기본 true. LLM 실패 시 description을 Google/MyMemory로 한국어화 |
| `LANGSMITH_API_KEY` / `LANGSMITH_PROJECT` / `LANGSMITH_TRACING` | - | LangGraph 트레이싱. API 키+`true` 둘 다 있어야 활성 |
| `CHECKPOINT_PATH` | - | 지정 시 LangGraph AsyncSqliteSaver, 미설정 시 MemorySaver |

VAPID 키 생성 예시:

```bash
pip install py-vapid
python - <<'EOF'
from py_vapid import Vapid
v = Vapid(); v.generate_keys()
print("VAPID_PUBLIC_KEY=" + v.public_key_urlsafe())
print("VAPID_PRIVATE_KEY=" + v.private_key_urlsafe())
EOF
```

`VAPID_SUBJECT`는 `mailto:` 주소.

## 2. Vercel 배포 (운영)

### 2.1 배포 방식

- Vercel serverless. `pyproject.toml`의 `[tool.vercel] entrypoint = "src.backend.main:app"`
- `src/backend/main.py`가 Vercel의 직접 로드 방식에 맞춰 `src/`를 `sys.path`에 추가한다
- 프론트엔드는 `npm run build` 산출물(`src/backend/static/*.js`)을 그대로 서빙 — 별도 프론트 배포 없음

### 2.2 환경변수 (Vercel 대시보드)

`.env.example` 전체를 Vercel env로 등록한다. 특히:

- `DATABASE_URL`: Supabase Postgres **pooler** 주소 (트랜잭션 풀러, 포트 5432/6543)
- `APP_ENV=release`: Swagger 비활성화
- `ADMIN_TOKEN`: Vercel Cron 호출 인증에도 사용

### 2.3 일일 수집 스케줄

serverless에서는 APScheduler가 상시 동작하지 않으므로 `vercel.json` Cron을 사용한다:

```json
{"crons": [{"path": "/api/admin/refresh", "schedule": "0 21 * * *"}]}
```

- UTC 21:00 = KST 06:00. Vercel Cron은 GET으로 호출 → `/api/admin/refresh`가 GET·POST 모두 허용(v1.0.2). `ADMIN_TOKEN`/`CRON_SECRET` Bearer 검증 후 `run_daily_collect` 실행
- Vercel Cron은 커스텀 헤더를 붙일 수 없지만, `CRON_SECRET` 환경변수가 설정되어 있으면
  `Authorization: Bearer <CRON_SECRET>`를 자동으로 보낸다. `CRON_SECRET`과 `ADMIN_TOKEN`을
  같은 값으로 두면 Cron 호출이 인증을 통과한다

### 2.4 iOS PWA Web Push

- iOS 16.4+에서 Web Push는 **홈 화면에 추가된 PWA**에서만 동작한다
- `/manifest.json` + 아이콘(`static/icon*.png`) 제공. `apple-touch-icon.png` 별도 존재
- 최초 1회는 Safari에서 사이트 열기 → 공유 → "홈 화면에 추가" → 홈 화면 아이콘으로 실행 후 구독

### 2.5 Supabase Postgres

- `DATABASE_URL=postgresql+psycopg://postgres.<ref>:<password>@aws-0-<region>.pooler.supabase.com:5432/postgres`
- `db.py`의 `make_engine`이 `postgres://`/`postgresql://`를 `postgresql+psycopg`로 정규화하고,
  Postgres에는 `pool_size=2, max_overflow=3, pool_recycle=300` 소형 풀 적용
- 스키마는 앱 시작 시 `create_all`로 자동 생성

## 3. Render 배포 (대안)

상시 서버가 필요하면 Render Web Service도 가능하다 (`render.yaml`, `Procfile` 제공).

- Runtime: Python, Build: `pip install -r requirements.txt`, Start: `python -m uvicorn backend.main:create_app --factory --host 0.0.0.0 --port $PORT`
- 무료 플랜은 ephemeral disk → SQLite 유실. Postgres `DATABASE_URL` 전환 필수
- 무료 플랜 spin-down 시 APScheduler 미발화 가능 → Render Cron Job으로 `python -m backend.cli_collect` 매일 등록 권장
- 이 구성에서는 APScheduler(로컬 KST 06:00)가 그대로 동작한다

## 4. 수집 쿼리 커스터마이징

`src/backend/queries.yaml`을 수정해 플랫폼별 검색 쿼리를 변경한다.
각 쿼리는 GitHub 검색 문법을 그대로 사용하며 `archived:false fork:false`를 포함해야 한다.
수정 후 재배포(또는 재시작)하면 다음 수집부터 적용된다.

## 5. 트러블슈팅

| 증상 | 원인 | 조치 |
|---|---|---|
| `/api/trending` items 빈 배열 | 아직 수집 전 | `/api/admin/refresh` 호출 또는 다음 스케줄 대기 |
| 요약이 description 반복 | `LLM_API_KEY` 미설정 또는 LLM 장애 | 키 확인, 로그에서 `LLM 호출 실패` 확인 |
| 푸시 버튼 무반응 | VAPID 키 미설정 | `vapid-key` API가 `{"key":""}` 반환 |
| 401 on refresh | `ADMIN_TOKEN` 불일치/미설정 | env 확인 |
| DB 오류 on Postgres | `psycopg` 미설치 또는 pooler 주소 오류 | `requirements.txt`의 `psycopg[binary]`와 pooler 호스트/포트 확인 |
| 스케줄 미실행 | Vercel Cron 실패 또는 시간대 | Vercel Cron 로그 확인, `schedule`은 UTC 기준 |
| 분류가 전부 `other` | `LLM_API_KEY` 미설정 (`llm_enabled=False`) | 키 등록 후 재수집 |
